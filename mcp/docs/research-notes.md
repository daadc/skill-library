# AST 知识检索 MCP：调研记录

> 状态：`DISCOVERY`。本文仅记录已核验的外部事实与由此导出的待验证假设；不将参考项目的宣传性性能数字作为本项目的目标或承诺。

## 已核验事实

| 编号 | 事实 | 来源与适用边界 |
|---|---|---|
| F-01 | `codebase-memory-mcp` 将 Tree-sitter AST 解析与部分语言的 LSP 类型解析结合，构造含函数、类、调用链、HTTP 路由和跨服务链接的本地持久化知识图谱，并提供 MCP 工具。 | 参考项目 README；这是参考实现能力，非本项目已具备能力。[1] |
| F-02 | MCP 工具面向模型自动发现和调用；服务端必须声明 `tools` 能力并响应 `tools/list`，工具应以稳定顺序暴露。工具可采用 JSON Schema 说明输入，响应可同时包含人读内容和结构化内容。 | MCP 工具规范 2026-07-28。[2] |
| F-03 | MCP 规范建议把人类保持在环中，并使可用工具与调用对用户可见。 | MCP 工具规范 2026-07-28。[2] |
| F-04 | 官方 Python SDK 支持构建暴露 tools、resources 和 prompts 的 MCP 服务，覆盖 stdio、Streamable HTTP 等标准传输；当前文档的运行要求为 Python 3.10 及以上。 | 官方 Python SDK 文档首页。[3] |

## 产品证据、假设与范围

| 分类 | 内容 | 状态与验证方法 |
|---|---|---|
| 用户请求（事实） | 用户希望参考 `codebase-memory-mcp` 的 AST 分析方式，构建能让 AI 快速检索并融会贯通知识点的工具，并放入当前项目的 `mcp/` 目录。 | 已由用户明确提供。 |
| 仓库观察（事实） | 当前项目以 `knowledge/` 下的 Markdown 知识卡、场景卡和 `sources.yaml` 为主要知识载体，顶层尚无现成 MCP 实现目录；已创建隔离的 `mcp/` 工作目录。 | 本地只读检查；实现将不改动原有知识文件。 |
| H-01（价值） | 将知识卡的主题、原则、风险、验证方法、引用和场景显式建模，并联合代码符号索引，可比全文扫描更快地向 AI 返回小而可追溯的相关上下文。 | 以确定性检索测试验证：主题查询必须返回知识卡节点、关联来源与场景；代码符号查询必须返回定义和关系。 |
| H-02（可行性） | 第一版以 Python 标准库 `ast` 支持 Python 源码、以结构化 Markdown/YAML 解析支持本项目知识库，可在不引入 Tree-sitter 原生构建链的前提下提供可用的本地 MCP 服务。 | 用本仓库样本和合成 Python 文件执行索引与查询测试。 |
| H-03（安全） | 仅允许读取显式指定根目录的受支持文件；所有工具均为只读，不执行代码、不访问网络、不写入被索引仓库。 | 单元测试验证根目录限制、路径穿越拦截与无写入副作用。 |

## 候选方案

| 方案 | 价值 | 成本与风险 | 本轮决议 |
|---|---|---|---|
| A：直接复刻参考项目 | 能获得多语言、调用链与大规模图谱能力。 | 需要 C/Tree-sitter/LSP 生态、持久化与多语言语义分析；范围与当前仓库的主要知识载体不匹配。 | 不采用。 |
| B：以文本/RAG 检索为主 | 实现快。 | 无法解释知识卡结构，也无法把代码符号、知识原则和验证方法连成可审计关系。 | 不采用。 |
| C：本地、只读的知识图谱 MVP | 为 Markdown/YAML 知识卡建立语义节点，为 Python 建立 AST 符号和轻量引用关系；经 MCP 提供确定性检索、邻域浏览与可读上下文。 | 首版只覆盖 Python 与知识库格式，需要清楚披露语言边界。 | 推荐并实现。 |

## 拟定最小可交付范围

本轮将交付一个以 stdio 运行的 Python MCP 服务。它递归读取用户指定的项目根目录（默认当前仓库），解析 `knowledge/**/*.md`、`sources.yaml`、场景卡和 Python 文件，构建内存中的可追溯图谱。工具层至少提供：索引状态、语义搜索、节点详情、相关知识/代码邻域和可压缩上下文包。服务没有写工具、没有执行工具、没有联网工具；超出根目录或不受支持的语言将返回明确、可恢复错误。

## 明确非目标

本轮不承诺 Tree-sitter 多语言覆盖、LSP 类型解析、向量检索、跨仓库同步、后台索引守护、代码改写、云端存储或自动修改知识卡。性能指标将在本仓库样本上记录，而非沿用参考项目的数字。
