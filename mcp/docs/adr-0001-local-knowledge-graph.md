## 1. 问题、用户结果与约束

用户需要一个受 MCP 调用的本地工具，使 AI 可以快速检索项目中的工程知识并连接到实现线索。当前项目的知识重点保存在 Markdown 知识卡、场景卡和 `sources.yaml` 中；仅用全文搜索无法将“原则—来源—风险—验证—场景”作为显式结构返回。用户提及的参考项目采用 AST 知识图谱，证明“以结构替代逐文件阅读”是值得验证的方向，但其多语言解析、LSP 与持久化规模不是本轮必要前提。[1]

本服务必须在调用者给定根目录内只读运行，禁止对被索引仓库写入、禁止执行任何代码、禁止联网与后台守护。输入与输出必须有稳定的结构，结果必须含可追溯定位，并限制数量/字符数以避免上下文失控。首版运行于 Python 3.10 及以上版本，以 stdio 方式由官方 MCP Python SDK 提供服务。[2] [3]

## 2. 调研证据与假设

| 类型 | 证据/假设 | 来源或定位 | 局限性 | 验证计划 |
|---|---|---|---|---|
| 事实 | 参考项目以 AST/LSP 构建本地知识图谱，提供可查询的代码结构。 | `mcp/docs/research-notes.md`；参考项目 README。[1] | 不代表本项目需要或能复刻其语言覆盖与性能。 | 不引用其性能数字；只验证本地 MVP 行为。 |
| 事实 | MCP 工具应声明工具能力，通过 JSON Schema 公开输入，且人类应能察觉和控制调用。 | MCP 工具规范。[2] | 具体客户端 UI 行为不由服务端控制。 | 以只读工具、清晰描述与 stdio smoke test 验证。 |
| 事实 | 当前项目知识卡包含标题、原则、来源、风险、验证和场景等结构。 | `knowledge/product-discovery/*.md` 与 `sources.yaml`。 | 不同领域卡片的字段表现可能不完全一致。 | 解析器按可选字段降级，测试覆盖缺失字段。 |
| 假设 | Markdown 结构 + Python AST 的最小图谱能满足第一阶段“检索并连接知识点”的需求。 | `mcp/docs/product-brief.md` H-01/H-02。 | 未经真实任务使用验证。 | 对现有卡片与合成 Python 模块运行端到端检索测试。 |

## 3. 领域、数据与交互影响

本服务的唯一 bounded context 是 **可追溯知识检索**。核心术语包括：**节点**（可定位的知识、来源、场景或代码符号）、**边**（包含、引用、调用、导入、术语关联）、**快照**（一次成功索引的只读内存图）、**上下文包**（受预算约束的、面向 AI 的证据集合）。被索引仓库仍然是所有文件的权威源；服务不拥有或修改任何业务数据。

节点 ID 由 `kind + relative_path + line_span + normalized_name` 经 SHA-256 截断派生，因而可以在同一文件内容未移动时稳定定位。图谱的写入只发生在服务进程内：先在临时图中完成构建，成功后以一次引用替换当前快照；构建失败不破坏上一版本快照。所有边均带关系类型与可解释理由，避免将统计相关性伪装为事实因果。

| 节点类别 | 权威来源 | 关键属性 | 最小关系 |
|---|---|---|---|
| `knowledge` / `scenario` | `knowledge/**/*.md` 的二级及以上标题区段 | 标题、正文、知识域、行号、章节字段 | `contains`、`cites`、`same_domain`、`shares_terms` |
| `source` | `knowledge/**/sources.yaml` | `source_id`、标题、URL、版本、claim_scope | `cited_by`、`same_domain` |
| `module` / `class` / `function` / `method` | `**/*.py` 的 Python AST | 合格名、签名、文档字符串、行号 | `contains`、`imports`、`calls`、`shares_terms` |

## 4. 决策驱动因素

决定优先考虑：当前知识格式的直接适配、可追溯性、对 AI 的低上下文成本、路径安全、实现可验证性、依赖规模和可逆性。系统不以未经本仓库验证的吞吐或延迟数字作为决策依据。

## 5. 备选方案

| 方案 | 收益 | 成本/风险 | 验证证据 | 可逆性/退出路径 |
|---|---|---|---|---|
| 保持简单：只用 `grep`/全文搜索 | 无服务依赖、即时可用。 | 缺少节点、关系、来源与上下文裁剪，无法表达知识结构。 | 现有知识卡具有可利用的标题/引用/字段结构。 | 随时可停止，无迁移。 |
| 直接引入 Tree-sitter + LSP + 持久化数据库 | 多语言和更丰富的语义关系。 | 原生构建、依赖、语言配置与运营复杂度高；当前项目尚无需求证据。 | 参考项目展示其可能性，但没有证明本项目需要。[1] | 可在后续把本图谱解析层抽象为 parser adapter 后加入。 |
| 采用本地 Markdown/YAML 图谱 + Python 标准库 AST | 直接覆盖当前知识资产、零数据库、可读、可测试、最小权限。 | 首版只保证 Python AST，跨语言关系较弱。 | 可由当前项目与合成样本立即验证。 | 可保持节点/边/工具接口不变，替换或增加解析 adapter。 |

## 6. 决定与理由

采用 **进程内、只读、根目录限制** 的图谱实现。知识层解析 `knowledge/` 下 Markdown 的标题区块、引用编号和关键标记字段，同时读取相邻 `sources.yaml` 的安全子集；代码层使用 Python 标准库 `ast` 建模模块、类、函数、方法、导入和直接调用。检索层采用大小写折叠词项匹配及字段权重，不接入嵌入模型；关系层允许以节点 ID 查详情与展开一跳或受控多跳邻域。

这是当前最小的可验证切片：它既保留知识卡中帮助判断的结构信息，又能从代码符号出发查到实现上下文。多语言 Tree-sitter、LSP 和持久化索引作为未来替代或扩展，不在当前范围内。

## 7. 后果与实施/迁移切片

实现分为四个可独立验证的切片。首先建立纯数据模型、路径边界与限制；其次实现 Markdown/YAML 节点和来源关系；第三实现 Python AST 节点与导入/调用关系；最后把统一查询能力注册为五个 MCP 只读工具。所有代码置于 `mcp/`，不改动现有知识库。构建新快照失败时保留最近成功快照；进程重启后需要显式重新索引，这是刻意的简单性取舍。

回滚方式为停止服务或删除 `mcp/` 目录；被索引项目不会被写入，因此没有数据恢复步骤。不可逆点为零。本决策的唯一外部依赖是官方 MCP Python SDK；依赖版本将锁定在兼容范围并通过本地测试验证。

## 8. 验证、观测与停止条件

质量门禁包括：对 Markdown、YAML、Python AST 和图谱关系的单元测试；对根目录越界、空查询、未知节点、超限和解析失败的负向测试；通过 MCP 客户端会话调用 `tools/list`、索引与查询工具的 stdio smoke test。索引结果返回文件/节点/边/跳过文件计数与耗时，可作为本地观测信息，但不视为生产 SLO。

若工具需要写入、执行、联网、读取根目录外文件，或出现不受控输出，则停止并修正设计。若真实用户任务显示 Python 覆盖不足或确定性召回无法满足需求，则以新的 ADR 比较 Tree-sitter、语言服务器和/或向量召回方案。
