# Product Brief：知识连通 MCP

## 问题与目标用户

目标用户是需要在本地工程知识库和代码之间进行技术判断的 **AI 编程助手及其使用者**。当前工作方式通常是由 AI 逐文件搜索和阅读，容易遗漏知识卡中的适用条件、风险、验证步骤与来源，并难以将它们与代码符号联系起来。用户明确要求借鉴 AST 分析型 MCP，提升知识检索速度，并将分散的知识点融会贯通。

本项目当前可直接观察到的证据是：`knowledge/` 已组织为领域目录、Markdown 知识卡、场景卡和 `sources.yaml`，而这类文件中的层级、引用、风险和验证结构尚未暴露为统一检索接口。尚无真实用户访谈、使用日志或耗时基线；因此，价值结论仍是待验证假设，而非已证实的业务收益。

## 期望结果、护栏与度量

最小结果是让 MCP 客户端能在一个明确的项目根目录内，先完成只读索引，再通过精确、可解释的工具快速得到：相关知识点、所依据的来源、适用条件、风险、验证方法、关联场景，以及与查询词匹配的 Python 符号和轻量结构关系。每个返回的结果都必须有稳定节点 ID、相对路径和行号或段落定位，避免 AI 将检索结果误认为无出处的结论。

| 指标类型 | 定义 | 本轮通过标准 |
|---|---|---|
| 任务成功 | 给定主题查询，工具能返回至少一个相关知识节点，并包含来源或验证字段；给定 Python 符号查询，能定位其定义。 | 自动化样本测试通过。 |
| 可追溯性 | 知识节点返回其路径、起止行、来源引用与关联关系。 | 所有知识检索结果均含定位字段；可调用详情工具展开。 |
| 边界安全 | 服务只读取索引根目录的允许文件，不写入、执行或联网。 | 越界路径与不支持路径测试均拒绝；测试过程无被索引项目写入。 |
| 响应约束 | 工具返回受 `limit` 和 `max_chars` 约束，避免向 AI 灌入无界全文。 | 所有列表和上下文工具实施安全上限。 |

## 研究方法、证据限制与待验证假设

本轮使用 **形成性本地原型验证**：对本仓库现有知识卡与合成 Python 文件运行索引、检索和错误路径测试。它验证技术可行性与接口正确性，不能替代真实用户行为研究。下一轮应在实际编码任务中记录首次命中率、后续追问次数、工具调用数和人工满意度，再决定是否需要引入 Tree-sitter、多语言语义或向量召回。

| 假设 | 类别 | 验证方式 | 通过/失败信号 |
|---|---|---|---|
| 知识卡结构化解析可保留其决策信息。 | 可行性 | 对样本卡片断言标题、原则、来源、风险和验证均可检索。 | 字段完整则通过；结构字段丢失则失败。 |
| AST 符号可成为知识主题与实现线索之间的轻量锚点。 | 可用性/可行性 | 对合成 Python 文件断言函数、类、导入和调用关系可被查询。 | 查询返回正确节点与关系则通过。 |
| 确定性词项评分对当前小型、结构化知识库足以提供可用的首版召回。 | 价值 | 以代表性主题查询验证排名和关联展开。 | 首条或前若干条命中预期知识域；否则记录词典/评分改进项。 |
| 只读、根目录限定的工具能降低 Agent 误操作面。 | 安全 | 越界、写入意图和不支持输入均显式失败。 | 无跨根目录读取、无写操作则通过。 |

## 约束与非目标

实现必须使用本地 Python 3.10 及以上版本，并以 stdio MCP 服务交付。首版只保证 Python 的 AST 解析；Markdown 和 `sources.yaml` 的解析针对当前知识库惯例实现稳健降级，不把任意 YAML 当作可执行配置。索引不持久化、不启动后台守护、不访问网络，并在每次构建索引时仅使用调用者提供的根目录。服务不会暴露写入、删除、执行、安装、Git 或网络调用工具。

不在本轮实现 Tree-sitter 的 158 语言覆盖、LSP 解析、跨进程增量索引、向量/嵌入模型、外部数据库、用户鉴权、多仓库联邦、自动知识生成或客户端 UI。本轮也不宣传或承诺参考项目的性能结果。[1]

## 方案比较与推荐范围

| 方案 | 价值 | 风险/成本 | 结论 |
|---|---|---|---|
| 直接采用多语言 AST/LSP 图谱 | 覆盖广，代码关系更丰富。 | 构建与运维复杂，且对以知识卡为主的当前仓库不是最小价值切片。 | 延后。 |
| 纯全文搜索 | 实现非常快。 | 缺乏知识结构、关系和代码符号，不能可靠支持“融会贯通”。 | 不采用。 |
| 知识卡语义图 + Python AST 图 | 直接覆盖知识载体与可运行代码；结构清晰、可验证且可扩展。 | 首版语言范围有限。 | 本轮推荐。 |

本轮最小范围包含五个只读 MCP 工具：`index_repository`、`search_knowledge`、`get_node`、`explore_connections` 与 `build_context_pack`。`index_repository` 显式触发索引；其余工具只查询当前内存快照。检索按标题、摘要、节标题、标签和符号名称执行确定性评分；邻域工具用于从一个节点沿引用、同文件、场景和代码调用关系扩展；上下文包工具把结果裁剪为可用于 AI 推理的紧凑、带出处内容。

## 用户流与验收标准

| 编号 | 参与者与前置条件 | 操作 | 可观察结果 | 失败与恢复 |
|---|---|---|---|---|
| AC-01 | AI 已启动服务，拥有允许访问的根目录。 | 调用 `index_repository(root)`。 | 返回文件数、节点数、边数、支持语言、跳过文件和构建时间。 | 根目录不存在、不可读或超过范围时返回结构化错误，不保留半成品快照。 |
| AC-02 | 索引成功。 | 调用 `search_knowledge(query, kinds, limit)`。 | 返回按评分排序且受限的节点摘要，每项包含 ID、类型、路径、定位和匹配证据。 | 空查询或无命中返回明确空集和建议，不抛出未处理异常。 |
| AC-03 | 搜索结果中存在节点 ID。 | 调用 `get_node(id)`。 | 返回节点的完整可读内容、属性和直接关系。 | 未知 ID 返回 `not_found` 错误。 |
| AC-04 | 需要把知识与实现线索结合。 | 调用 `explore_connections(seed_id, relation?, depth=1)`。 | 返回有类型、有方向的邻接节点及其关系原因。 | 深度/数量超出上限时进行裁剪并报告截断。 |
| AC-05 | AI 要形成回答或下一步编码上下文。 | 调用 `build_context_pack(query, max_chars)`。 | 仅返回受字数限制的相关知识、代码符号、风险、验证和来源定位。 | 未索引或 `max_chars` 非法时返回可恢复错误。 |
| AC-06 | 任意工具输入了根目录外路径、父目录跳转或不支持文件。 | 尝试索引/查询。 | 读取被拒绝，服务没有写入或执行任何被索引文件。 | 返回 `invalid_root`、`path_outside_root` 或 `unsupported_input`。 |

## 技术、数据与可靠性依赖

服务依赖官方 Python MCP SDK 的 stdio 传输能力及 Python 标准库的 `ast`、`pathlib`、`re`、`json` 和 `hashlib`。图谱在进程内存在，索引失败时保留上一次成功快照；新的成功索引以原子替换方式更新快照。所有文件访问通过已解析的根目录和允许扩展名控制；单文件和总文件数量设置默认限制，并把忽略原因随索引结果返回。

## 验证计划与决策责任

工程验收由自动化单元测试、服务内调用测试与 stdio MCP smoke test 组成。测试须覆盖 Markdown 结构、YAML 来源提取、Python AST 符号与调用、确定性排序、邻域限制、空/非法输入、根目录限制和上下文截断。用户作为产品与未来发布 owner，负责在真实 MCP 客户端中的接入与后续范围取舍；本地 R1 实现与验证可在隔离工作树内完成。
