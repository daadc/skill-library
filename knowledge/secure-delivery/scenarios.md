# 安全交付场景卡

## SC-SD-001：新增批量导入 API 与异步 worker

**输入。** 多租户系统增加 CSV 上传、异步处理和结果下载；前端、Go API、对象存储、Kafka worker、PostgreSQL 和 Redis 都会受影响。

**必须协作。** 产品确认用户/权限/保留期；架构和后端定义 Context、OpenAPI/事件、对象/属性/功能授权、幂等和错误；平台/SRE 定义容器/secret/网络/资源边界；韧性定义请求和队列预算；质量执行权限/跨租户/重复/异常文件/资源消耗/契约测试；文档治理维护交互契约、Runbook 和发布契约。

**安全门禁。** 任一项未知则不可声称可上线：上传大小/格式/恶意文件处理；对象存储访问范围；租户与对象授权；后台任务发起/查询/下载权限；重试/DLQ/重放；错误信息是否泄露；容器制品来源；日志中是否含 PII/secret。

## SC-SD-002：依赖/基础镜像安全更新

**输入。** 扫描或供应商公告指出基础镜像或直接依赖有漏洞。

**通过条件。** 能从制品契约定位受影响版本和部署环境；评估可利用性/暴露面/业务影响；建立可复现升级分支；CI 重新构建、测试和扫描；R2/R3 发布通过 release contract；回退与发布后观测清晰。不得因为“有 CVE”自动升级而忽略破坏兼容性，也不得因为“当前没有被攻击”无限期拖延。

## SC-SD-003：AI 生成的高风险权限改动

**输入。** AI 建议将某管理 API 的 middleware 改为“内部访问即可”。

**通过条件。** 编排器定级 R2/R3，阻止直接合并/发布；安全交付、后端、产品、架构、质量和文档治理分别审查领域权限、现有调用者、日志、测试、ADR 和回退；必须由人类 owner 批准。AI 的推荐、测试和静态检查都只是证据，不替代责任判断。
