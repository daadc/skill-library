# 并发与韧性工程场景卡

## SC-RES-001：下游数据库慢导致 API 级联超时

**输入。** 数据库 P99 从 80ms 升至 2s；API 网关收到大量 504；应用的线程、连接和队列都在增长。

**责任路由。** `platform-sre-engineer` 建立时间线和饱和证据；`backend-runtime-engineer` 审查 deadline、超时、取消、重试和连接池；`data-engineer` 定位查询/锁/复制/资源问题；`cloud-native-data-platform-engineer` 审查入口限流、舱壁和集群资源；`quality-engineer` 把故障模型加入回归。

**验证项目。**

1. 检查是否存在多层重试；计算理论最大放大倍数。
2. 检查上游 deadline 是否小于下游超时，及请求取消是否传播。
3. 验证独立连接/线程池和队列上限是否阻断横向耗尽。
4. 对低优先级工作启用早拒绝或暂停，对关键读路径验证明确的缓存/降级语义。
5. 数据库恢复后，检查连接池、积压、重试令牌与熔断器能否平滑恢复，而非瞬间重压。

**通过条件。** 产出可量化的预算、池/队列边界、按错误分类的重试规则、降级体验和压测/故障注入证据。

## SC-RES-002：支付依赖返回间歇性 503

**输入。** 外部支付提供方在 5 分钟内 20% 请求返回 503，业务不能重复扣款。

**通过条件。** 不把“重试三次”作为唯一答案；必须明确幂等键、请求状态机、超时与总 deadline、单层有限重试、退避/抖动、熔断 Open/Half-Open、用户呈现的“处理中”语义、对账与人工修复路径。验证网络超时但服务端已成功的情况。

## SC-RES-003：单租户洪峰影响所有客户

**输入。** 单个企业租户触发批量同步，Kafka backlog、Redis 热键和应用 worker 全部升高，其他租户延迟恶化。

**通过条件。** 设计并验证租户级入口限额、任务配额/队列或 cell、按租户可观测性、可恢复的公平调度和关键客户保护。不能只通过全局扩容或全局限流解决。
