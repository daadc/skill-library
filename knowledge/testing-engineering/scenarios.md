# 测试工程场景卡

## SC-TEST-001：订单创建 API 增加库存预占与事件发布

**风险。** 重复提交、并发库存竞争、DB 提交与事件发布不一致、消费者混合版本、支付/库存依赖超时。

**最小证据。** 领域规则与并发单元测试；Postgres 事务/约束和迁移集成测试；API 授权/幂等/错误 contract；outbox/事件 key/重复/乱序/重放测试；库存依赖 timeout/重试/熔断故障注入；最小用户旅程 E2E；发布后订单成功率、超卖、事件积压和错误预算观察。

**拒绝条件。** 只有 mock 单测；没有跨服务契约；不知道重复事件如何处理；没有对账/恢复；将“event 已发送”误写为“业务已完成”。

## SC-TEST-002：Kubernetes 配置和 Nginx 限流改动

**风险。** 配置语法正确但路径/版本不兼容，限流误伤正常流量，资源限制导致排队/重启，回滚配置与数据不兼容。

**最小证据。** 配置/schema/policy 检查；容器构建与启动探针；预发黑盒请求和白盒指标；请求量级/突发/错误/延迟/饱和测试；回滚演练；告警/Runbook 更新；灰度期间服务/用户/业务信号观察。

## SC-TEST-003：大型回归失败或不稳定

**输入。** 跨服务 E2E 测试在 CI 中偶发失败，阻塞主干。

**行动。** 明确 owner；记录环境、种子数据、依赖版本、时间与 trace；区分产品缺陷、测试 bug、环境污染与非确定性；优先缩小 SUT/场景或为依赖建立高保真 fake；不能通过无限重试掩盖 flaky 测试；若临时豁免，必须有期限、风险 owner、替代验证和删除计划。
